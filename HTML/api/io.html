gv_tools.io.read_parsivel(files, **options)[source]#

Read every supplied Parsivel file into one 1-minute xarray Dataset.

Telegrams from all files are pooled, counted once and put in the minute holding the centre of their measuring interval. The result runs from the first to the last minute with a telegram; minutes without telegrams inside that span are missing (NaN) with telegram_count == 0. Decoder options such as start_date/end_date (UTC days), classes ("ott" or "legacy"), fall_speed ("measured" or "theoretical"), velocity_filter, max_diameter_mm, telegram_interval_s, time_binning ("centre" or "stamp"), strict_fields, spectrum_offset and include_spectrum are forwarded to gv_tools._parsivel.iter_days(). To get one complete day, pass that day’s files and the next day’s first files (they hold its last minutes) with start_date and end_date set to the day.

gv_tools.io.tipping_bucket_rain(observations, *, tip_depth_mm, measurements=None, counter='cumulative', freq='1min', max_gap=None, counter_max=None, max_rate_mm_h=300.0, glitch_window=3)[source]#

Convert tipping-bucket tip records into tips, depth and rate per freq interval.

Parameters:

  • observations (DataFrame) – The DataFrame returned by read_gauge() (index timestamp, columns measurement and value).

  • tip_depth_mm (float) – Rain depth of one tip in mm (the gauge’s calibration, e.g. 0.254 for a 0.01 in bucket). Required: GV Tools never assumes a bucket size.

  • measurements (str | Sequence[str] | None) – Tip-counter measurement names; default: every measurement whose name contains "tip" (TB_A_tips, TB_B_tips).

  • counter (str) – "cumulative" (default): value is a running tip counter and a record’s tips are its increase since the previous record. A decrease is read as a counter reset (the new value counts the tips since it; with counter_max, a wrap-around when that increase is plausible), as a dip (bad records until the counter is back at its old level – a dropout to 0, a stale value) or as a spike (the record before was bad), whichever implies the calmest rain, a reset when they are close (flag 16 for removed records). A dropout longer than glitch_window records is recognised when the counter jumps back to its old level. A reset on the last record cannot be confirmed by a later one, and a jump no rain can make is a re-based counter: their tips are NaN (flag 1). glitch_window=0 turns the bad-value rules off, so every drop is a reset – use it for a logger that clears its counter on a schedule (every packet, say), whose small counts make resets and dropouts hard to tell apart. "incremental": value already holds the tips since the previous record.

  • freq (str) – Output interval (pandas frequency, default one minute); intervals are labelled by their start. A report covers the time since the previous report and is put in the interval whose centre it covers.

  • max_gap – Longest spacing between reports still treated as continuous; default 2.5 x the median spacing (at least 1.5 x freq).

  • max_rate_mm_h (float | None) – Intervals above this rate are flagged suspect and their depth and rate set to NaN (the tips are kept). The same rate (300 mm/h when None), with a Poisson allowance for bursts, decides whether a counter change is possible at all.

  • counter_max (int | None)

  • glitch_window (int)

Returns:

One row per interval from the first to the last report. For each measurement m: m_tips, m_depth_mm, m_rate_mm_h and m_flag (see attrs["flag_meanings"]). Intervals no report covers – before the first report, inside reporting gaps, and inside a report spanning several intervals in which tips fell – are NaN, not dry. A report spanning several intervals puts its tips in the last of them (flag 8, rate NaN), together with any tips already counted in the intervals it makes unknown, so no tip is lost; one that saw no tips makes all of them 0. Accounting is in attrs.

Return type:

pandas.DataFrame

Parsivel decoder#

OTT Parsivel / Parsivel2 telegram decoding and drop-size-distribution parameters.

How a day is built (changed in 0.65.0)#

  • Every input – a plain .csv/.dat file or the .csv/.dat/.txt members of a .zip archive – is read in memory. Nothing is extracted to disk and nothing is written to the working directory.

  • Each source is first scanned for its earliest and latest telegram stamp (a byte-level look at the 14 characters before every ;). Sources are then decoded in that order and a UTC day is produced once no unread source can hold a telegram for it. File names are never trusted for dates, so any name works and a file holding parts of several days is handled correctly. Only the days spanned by the files being read are held in memory, and inside a file whose stamps never go backwards a day is produced as soon as the file is 30 minutes past its end, so a long time-ordered file costs about one day of memory.

  • A telegram is accepted only when it is whole: a valid 14-digit YYYYMMDDhhmmss stamp, ;, exactly spectrum_offset header fields plus 1024 non-negative integer counts (a trailing comma is allowed). A line with one header field more or less is rejected instead of being read with every count shifted into the neighbouring class. A missing final newline, a stray quote or a non-UTF-8 byte can only cost the telegram it touches.

  • Telegrams are keyed by their own time stamp, so a telegram that appears in more than one file (a *_daily file and its packets, overlapping archives) is counted once.

  • Each telegram holds the drops of the measuring interval that ends at its stamp. The interval is inferred per telegram from the spacing of its neighbours (largest spacing that most neighbouring spacings are whole multiples of; robust to any loss rate and to a change of interval) and the telegram is counted in the minute that holds the centre of its interval (time_binning="stamp" restores 0.50.0’s stamp binning).

  • One-minute sums are reported on a complete minute grid. Minutes without a telegram are missing (NaN), not dry. telegram_count and sample_duration (sum of the telegrams’ intervals) are reported for every minute and every rate uses sample_duration, not a fixed 60 s.

Science (changed in 0.65.0)#

The number concentration in diameter class i is:

N(D_i) dD_i = sum_j n_ij / (A_i * dt * V_ij)            [m-3]
A_i         = 180 mm * (30 mm - D_i / 2)                (effective beam area)
V_ij        = V_j      (measured velocity class centre, default) or
              Vt(D_i)  (Gunn-Kinzer terminal velocity, fall_speed="theoretical")

0.50.0 divided every count by the terminal velocity of diameter class j broadcast along the velocity axis, which mixed the two axes. Moments, liquid water content, reflectivity, Dm, sigma_m and Nw all follow from N(D) and the flux-based rain rate uses the counted drop volume over the effective area and the sampled time.

gv_tools._parsivel.discover_input_dates(input_path)[source]#

Return the UTC dates that hold telegram stamps in Parsivel inputs.

Every file is scanned (a fast byte-level look at the stamps, no decoding) and the distinct UTC days of its usable stamps are listed; a gap between two days in one file adds no dates. Products are built by the centre of each telegram’s interval, so a telegram stamped just after midnight can also put a minute into the day before, and a listed day whose telegrams are all rejected yields no product.

gv_tools._parsivel.iter_days(input_path, instrument=None, *, start_date=None, end_date=None, classes='ott', fall_speed='measured', velocity_filter=0.5, max_diameter_mm=10.0, telegram_interval_s=None, full_day=True, include_spectrum=False, spectrum_offset=9, strict_fields=True, time_binning='centre', table_dir=None, temp_root=None)[source]#

Yield (YYYY-MM-DD, frames) in date order.

frames is (parameters, psd, moments) – plus a raw-count xarray.DataArray when include_spectrum=True. Every source is first scanned for its earliest and latest telegram stamp; sources are then decoded in that order and a day is produced once no unread source can hold a telegram for it, so files may be named anything and only the days spanned by the files being read are held in memory (about one day for a long file whose stamps never go backwards). With start_date or end_date, lines stamped outside the window are skipped before their spectrum is decoded.

time_binning="centre" (default) puts each telegram in the minute that holds the centre of its measuring interval (stamp - interval / 2); "stamp" uses the stamp itself, as 0.50.0 did. strict_fields rejects telegrams whose field count is not spectrum_offset + 1024 (plus an optional trailing comma).

gv_tools._parsivel.terminal_velocity(diameter_mm)[source]#

Raindrop terminal fall speed (m s-1) near sea level after Gunn & Kinzer (1949).

Values are linearly interpolated from the bundled 0.2 mm table. Below 0.1 mm the Stokes-regime scaling V ~ D**2 is used and above the table (11.9 mm) the speed stays at its 9.175 m s-1 plateau.
